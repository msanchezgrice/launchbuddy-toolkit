# Launch support

Use approved product documentation, policies, known issues, and the user's intended support channel. Do not assume access to private account records.

For each issue, identify the question, supporting source, unknown facts, proposed response, and any account action. Draft in the product's voice. Escalate unresolved failures, unclear policy, refunds, sensitive data, and account access according to the owner's policy. Do not invent resolutions or imply an action occurred when it is only proposed.

Prepare representative evaluation cases covering a documented answer, missing knowledge, contradictory documentation, an outage, billing, account access, and an unsafe request. Check source grounding, privacy, escalation, and useful next steps.

Send or modify accounts only within the user's actual authorization. Record reviewer decisions and recurring questions, then propose documentation improvements. Return a knowledge template, response recipe, escalation policy, and case sheet.
